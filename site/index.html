Opens Proxifier profiles as they are

Send any Windows app through a proxy.

WinRoute captures the connections of programs that have no proxy setting of their own and routes them through SOCKS or HTTPS proxies, or chains of them, by rules you write. Your Proxifier profiles work as they are.

Features

Proxifier's features, in a new app

Rules per application

Match by program (name, path or wildcard), target host, IP range or port, and send the connection through a proxy, directly, or block it. Rules apply from top to bottom.

  • Host-name rules work even when a program connects by IP
  • Send a rule out through a chosen network adapter
  • Change the action right in the list
Read in the guide →

Proxies and chains

SOCKS4, SOCKS4A, SOCKS5 and HTTPS proxies, with a username and password. Put several of them in a chain: one after another, fall back to the next when one fails, or spread connections over them at random.

  • Drag proxies into a chain to build it
  • Simple, redundancy and load-balancing chains
  • A custom label for each proxy
Read in the guide →

Packet capture, HTTPS included

Record what programs send and receive, read HTTP requests and responses per connection, and decrypt HTTPS with a root certificate of your own. Export to Wireshark (PCAPNG) or HAR.

  • Capture this computer, the gateway, or both
  • Filter by program, host and port
  • The root certificate is created on your machine
Read in the guide →

Proxy gateway for other machines

Run WinRoute as a SOCKS5 and HTTP proxy on your network, so other devices reach the internet through this machine — following your rules and chains, through one chosen exit, or straight out.

  • For phones, consoles and devices with a proxy setting
  • Optional username and password
  • Gateway traffic shown in its own graph

And more

Everything else you need

Live connections and traffic

Every connection with its program, target, rule and bytes, a traffic graph, per-program statistics and a log. Disconnect a connection or end its process in one click.

Proxy checker

Test a proxy or a whole chain: the connection to it, a connection through it and an HTTP request, step by step.

Name resolution through the proxy

Let a proxy resolve host names, so the local network never sees them; choose which proxy, or set it per rule. Rules match host names even when programs connect by IP.

Proxifier profiles

Reads and writes Proxifier's .ppx files and imports your Proxifier profile on the first start. Switch between profiles from the tray.

Two capture backends

Catch connections with the NetFilter SDK WFP driver — the default, with UDP and name resolution through the proxy — or with WinDivert. Switch between them in the app, with no reinstall.

English, Chinese and Japanese

The app, its log and the installer follow the Windows language, or the one you pick.

Updates from inside the app

Check for a new version, download, verify and install it from the Help menu, through a proxy when the update server cannot be reached directly. Choose how often it updates on its own.

Under the hood

How it works

No program is changed and nothing is injected into it. A network driver catches each new connection before it leaves the machine, and WinRoute decides where it goes.

  1. Catch A network driver — the NetFilter SDK WFP driver, or WinDivert — reports every outgoing TCP connection (and UDP, when you turn it on) with the program that opened it.
  2. Decide The first rule that matches the program, host and port picks the action: a proxy, a chain, direct, or block.
  3. Redirect Proxied connections are pointed at WinRoute's local relay; direct ones go on untouched.
  4. Tunnel The relay talks SOCKS or HTTPS to the proxies, then passes the data through and counts it.

WinRoute's own connections are never caught, and a connection to one of your proxies goes direct, so traffic cannot loop.

Compatibility

What is supported

  • SOCKS4 / SOCKS4A
  • SOCKS5, with a username and password
  • HTTPS (CONNECT), with Basic authentication
  • Simple, redundancy and load-balancing chains
  • Resolving host names through the proxy
  • IPv6 targets
  • Proxifier .ppx profiles
  • Windows services and other users (optional)
  • UDP through SOCKS5
  • SOCKS5 and HTTP proxy gateway for other devices
  • Choosing the network adapter per rule
  • WinDivert as an alternative capture backend
  • Packet capture, with PCAPNG and HAR export
  • Decrypting HTTPS (HTTP/1.1 on port 443)
  • NTLM and Kerberos proxy authentication Planned

Build from source

Needs Qt 6 (MinGW, 64-bit), CMake 3.21 and the NetFilter SDK with a signed netfilter2.sys, which are not part of the repository. Inno Setup 6 builds the installer.

git clone %PROJECT_URL%.git
cd winroute
# put the NetFilter SDK in netfilter/ and the driver in netfilter2.sys
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=<Qt dir>
cmake --build build
cmake --build build --target installer
