# 解密 HTTPS

开启后，抓包里的 HTTPS 连接显示为明文。

## 原理

WinRoute 对抓包范围内的 443 端口连接做中间人：

1. 读取程序发出的 TLS 握手里的域名（SNI），用 WinRoute 的根证书为这个域名临时签发证书，与程序建立 TLS 连接；
2. 同时以客户端身份连接真实服务器，并校验服务器的证书；
3. 在两条 TLS 连接之间转发数据，抓包里记录的就是明文。

如果真实服务器的证书校验失败，WinRoute 会断开连接，不会把不可信的服务器放行给程序。

## 解密本机程序

1. 在抓包页勾选 **解密 HTTPS：本机**，并确保 **抓取：本机** 已勾选、抓包已开始。
2. 还没有根证书时，WinRoute 会让你填写证书的 **通用名称**、**组织** 和 **有效期**，然后生成证书并安装到 Windows 的受信任根证书。
3. Chrome、Edge 等使用系统证书库的程序会直接信任这个证书。

::: tip Firefox
Firefox 使用自己的证书库。在 **根证书...** 里导出证书，再在 Firefox 的“设置 > 隐私与安全 > 证书 > 查看证书 > 证书颁发机构 > 导入”中导入。
:::

## 解密代理网关上的设备

1. 在抓包页勾选 **解密 HTTPS：代理网关**，并确保 **抓取：代理网关** 已勾选。
2. 还没有根证书时，WinRoute 会先创建一个。这个证书是给其他设备用的，不会安装到本机。
3. 在 **根证书...** 里 **导出** 证书（`.crt`），把它安装到手机、其他电脑等设备的受信任根证书中。
4. 只有通过 SOCKS5 或 HTTP CONNECT 连到 443 端口的连接会被解密。

本机和代理网关的解密开关相互独立，可以只开其中一个。

## 根证书管理

![根证书窗口](/images/root-cert.png){width=570}

点 **根证书...** 可以看到证书的状态（未创建、已创建但本机不信任、已创建且本机信任）、主题、有效期、序列号和 SHA-256 指纹，并可以：

| 按钮 | 作用 |
| --- | --- |
| 生成... | 创建根证书 |
| 安装 | 安装到本机的受信任根证书 |
| 删除 | 从本机的受信任根证书中移除 |
| 导出... | 保存为 `.crt` 文件，给其他设备或 Firefox 导入 |
| 重新生成... | 换一个新证书。之后所有设备都要换装新证书 |

::: danger 保管好私钥
根证书的私钥保存在 `%APPDATA%\WinRoute\ca`。拿到它的人可以冒充任何网站骗过信任这个证书的设备。不要外传；不再需要解密时，从本机和其他设备上删除这个证书。
:::

## 限制

- 只解密 TCP 443 端口。
- 会把 HTTP/2 协商降为 HTTP/1.1。不解密 QUIC（HTTP/3），它走 UDP。
- 使用证书固定（certificate pinning）的程序会拒绝连接。请用[抓包过滤](./capture#过滤)把它们排除。
