# 解密 HTTPS

启用后，抓包中的 HTTPS 连接以明文显示。

## 工作原理

WinRoute 对抓包范围内的 443 端口连接进行中间人解密：

1. 读取应用程序 TLS 握手中的域名（SNI），使用 WinRoute 根证书为该域名签发临时证书，与应用程序建立 TLS 连接；
2. 同时作为客户端连接实际服务器，并校验服务器证书；
3. 在两条 TLS 连接之间转发数据，抓包中记录的即为明文。

如实际服务器的证书校验失败，WinRoute 将断开连接，不会将不可信的服务器提供给应用程序。

## 解密本机应用程序

1. 在抓包页勾选 **解密 HTTPS：本机**，并确认已勾选 **抓取：本机** 且抓包已开始。
2. 如尚未创建根证书，WinRoute 会要求输入证书的 **通用名称**、**组织** 和 **有效期**，然后生成证书并安装到 Windows 的受信任根证书颁发机构。
3. Chrome、Edge 等使用系统证书存储的应用程序将信任该证书。

::: tip Firefox
Firefox 使用独立的证书存储。请在 **根证书...** 中导出证书，然后在 Firefox 的“设置 > 隐私与安全 > 证书 > 查看证书 > 证书颁发机构”中导入。
:::

## 解密代理网关设备

1. 在抓包页勾选 **解密 HTTPS：代理网关**，并确认已勾选 **抓取：代理网关**。
2. 如尚未创建根证书，WinRoute 会先创建证书。该证书供其他设备使用，不会安装到本机。
3. 在 **根证书...** 中 **导出** 证书（`.crt`），并将其安装到手机、其他计算机等设备的受信任根证书中。
4. 仅解密通过 SOCKS5 或 HTTP CONNECT 连接到 443 端口的连接。

本机与代理网关的解密设置相互独立，可只启用其中之一。

## 根证书管理

![根证书窗口](/images/root-cert.png){width=570}

**根证书...** 窗口显示证书的状态（未创建、已创建但本机未信任、已创建且本机已信任）、通用名称、组织、有效期和 SHA-256 指纹，并提供以下操作：

| 按钮 | 功能 |
| --- | --- |
| 生成... / 重新生成... | 创建根证书；重新生成后，所有设备均须安装新证书 |
| 安装 | 安装到本机的受信任根证书颁发机构 |
| 删除 | 从本机的受信任根证书颁发机构中移除 |
| 导出... | 保存为 `.crt` 文件，供其他设备或 Firefox 导入 |

::: danger 私钥的保管
根证书的私钥保存在 `%APPDATA%\WinRoute\ca`。持有该私钥者可对信任此证书的设备冒充任意网站。请勿泄露私钥；不再需要解密时，请从本机和其他设备上删除该证书。
:::

## 限制

- 仅解密 TCP 443 端口。
- HTTP/2 协商降级为 HTTP/1.1；不解密基于 UDP 的 QUIC（HTTP/3）。
- 使用证书固定（certificate pinning）的应用程序将拒绝连接，请通过[抓包过滤](./capture#过滤)将其排除。
