# 代理检测

菜单：**工具 > 代理检测...**，或工具栏中的 **代理检测**。

选择要测试的代理服务器或代理链，输入 **目标主机** 和 **端口**，然后单击 **开始测试**。

![代理检测](/images/checker.png){width=623}

## 测试项目

WinRoute 依次执行以下测试，并显示每项的结果和耗时：

1. **连接测试**：能否连接到代理服务器。
2. **通过代理服务器连接测试**：能否经由代理服务器连接到目标主机。
3. **HTTP 请求测试**：经由代理服务器发送 HTTP 请求，并显示响应状态。端口为 443 时，先进行 **TLS 握手测试**。
4. **UDP 支持测试**：仅针对 SOCKS5 代理。向代理服务器申请 UDP 中继，并经由中继向 `8.8.8.8` 发送 DNS 查询；收到应答即表示该代理支持 UDP 转发。
5. **UDP 可达性与 NAT 测试（STUN）**：仅针对 SOCKS5 代理。经由中继向若干公共 STUN 服务器并发请求，验证代理能否将 UDP 送达 **任意主机**（而非只有 DNS）；再对比两台服务器看到的公网端点，判定出口的 NAT 映射：**端点无关（full-cone）** 适合 P2P 游戏，**对称型** 则即使普通 UDP 可用，Steam 中继等 P2P 也很可能失败。服务器可勾选预置（名称见复选框、地址见提示）或在 **自定义** 框补充（`host:port`，用 `;` 或空格分隔）；整项可用标题处的复选框停用，且容忍个别服务器不可达——只要有一台回复即判定可达。

测试结束后显示“代理服务器工作正常”，或在失败的步骤中给出原因，例如：

- 身份验证失败
- 代理服务器需要身份验证
- 10 秒内无响应
- 不是 SOCKS5 代理服务器
- UDP 中继在 5 秒内无应答（UDP 可能被阻止）

UDP 相关测试未通过不影响整体结果，仅表示该代理服务器无法转发 UDP。

::: tip
“UDP 支持测试”只证明中继能完成一次 DNS 往返；有些代理只放行 53 端口的 UDP（常见于按端口分流的 xray 配置），会在这里显示通过，但游戏联机仍失败。“UDP 可达性与 NAT 测试”正是为区分这种情况而设。
:::

::: tip
添加或编辑代理服务器时，窗口中的 **检测** 按钮也会打开此工具。
:::
