# 常见问题

## 某个程序没有走代理

1. 看日志里这个连接命中了哪条规则。规则从上往下匹配，前面一条更宽泛的规则可能先命中了。
2. 程序是 Windows 服务或以其他用户身份运行时，要在 [服务和其他用户](./advanced#服务和其他用户) 里开启。
3. UDP 默认直接放行，要开启 [通过 SOCKS5 转发 UDP](./advanced#通过-socks5-转发-udp)，且动作必须是单个 SOCKS5 代理。浏览器的 QUIC（HTTP/3）就是 UDP。
4. ping、tracert 使用 ICMP，无法走代理。

## 用了一段时间后，所有连接突然都失效了

使用演示驱动时，拦截的连接总数达到上限后会停止工作，要重启 Windows 才能恢复。可以在 **工具 > 网络驱动** 换成驱动 A 或 B，或改用 WinDivert 后端。见[安装与网络驱动](./install#切换拦截后端和驱动)。

## 本机的代理客户端（v2ray、Clash 等）自己也被代理了，形成环路

确认 [连接环路检测](./advanced#连接环路检测) 已开启。WinRoute 会识别监听代理端口的程序，让它自己的连接直连。也可以为这个程序写一条“直接连接”规则放在最上面。

## 代理只接受域名，不接受 IP

在代理的 **高级...** 里勾选 [代理请求中尽量使用目标主机名](./proxies#高级设置)，或开启 [通过代理解析主机名](./dns#通过代理解析主机名)。

## 开启 HTTPS 解密后，浏览器提示证书错误

说明这台设备不信任 WinRoute 的根证书。本机请在 **根证书...** 里点 **安装**；Firefox 和其他设备需要导出后手动导入。某个程序始终报错时，它可能使用了证书固定，请用抓包过滤把它排除。见[解密 HTTPS](./https)。

## 其他设备连不上代理网关

检查 Windows 防火墙是否放行网关端口，设备和本机是否在同一网段，路由器是否开启了 AP 隔离。见[代理网关](./gateway#在其他设备上使用)。

## 能和 Proxifier 一起用吗

配置文件可以互相导入导出，但两者都会拦截连接，不能同时运行。
