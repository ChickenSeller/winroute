# 常见问题

## 应用程序未经由代理连接

1. 在日志中确认该连接匹配的规则。规则按自上而下的顺序匹配，排列在前且条件较宽的规则可能先行匹配。
2. 如应用程序为 Windows 服务或以其他用户身份运行，须在[服务和其他用户](./advanced#服务和其他用户)中启用相应选项。
3. UDP 默认直接放行。须启用[通过 SOCKS5 转发 UDP](./advanced#通过-socks5-转发-udp)，且规则操作须为单个 SOCKS5 代理。浏览器的 QUIC（HTTP/3）即属于 UDP 流量。
4. ping、tracert 使用 ICMP 协议，无法经由代理转发。

## 运行一段时间后所有连接均失效

使用演示驱动时，拦截的连接总数达到上限后将停止工作，须重新启动 Windows 才能恢复。可在 **工具 > 网络驱动** 中改用驱动 A 或 B，或改用 WinDivert 后端，参见[安装与网络驱动](./install#切换拦截后端和驱动)。

## 本机的代理客户端（如 v2ray、Clash）自身的连接也被转发，形成环路

请确认已启用[连接环路检测](./advanced#连接环路检测)。WinRoute 会识别监听代理端口的进程，使其自身的连接直接连接。也可为该程序创建一条“直接连接”规则，并将其置于列表顶部。

## 代理服务器仅接受域名，不接受 IP 地址

在代理服务器的 **高级...** 中勾选[代理请求中尽量使用目标主机名](./proxies#高级设置)，或启用[通过代理解析主机名](./dns#通过代理解析主机名)。

## 启用 HTTPS 解密后，浏览器提示证书错误

表示该设备未信任 WinRoute 的根证书。本机请在 **根证书...** 中单击 **安装**；Firefox 和其他设备须导出证书后手动导入。如某一应用程序持续报错，可能是其使用了证书固定，请通过抓包过滤将其排除。参见[解密 HTTPS](./https)。

## 其他设备无法连接代理网关

请确认 Windows 防火墙已放行网关端口、设备与本机位于同一网段，且路由器未启用 AP 隔离。参见[代理网关](./gateway#在其他设备上使用)。

## 能否与 Proxifier 同时使用

两者的配置文件可相互导入导出，但均会拦截网络连接，不能同时运行。
