# 抓包

菜单：**工具 > 抓包**。打开后，主窗口会多出一个 **抓包** 标签页。

抓包记录经过 WinRoute 的连接收发的应用层数据，用于调试程序的网络行为。抓到的内容只保存在本机内存里，不会上传。

![抓包页](/images/capture.png){width=1103}

第一次开始抓包时，WinRoute 会提示：抓包内容只保存在本机，开启 HTTPS 解密后可能包含密码等明文，导出或分享时要注意。

## 工具栏

```
[开始] [清除] [导出...] [过滤...] | 抓取：☑本机 ☑代理网关 | 解密 HTTPS：☐本机 ☐代理网关 [根证书...]
```

| 控件 | 作用 |
| --- | --- |
| 开始 / 暂停 | 开始或暂停记录 |
| 清除 | 清空已记录的内容 |
| 导出... | 导出为 PCAPNG 或 HAR，见下文 |
| 过滤... | 决定抓哪些连接，见下文 |
| 抓取：本机 | 记录本机程序的连接 |
| 抓取：代理网关 | 记录其他设备经[代理网关](./gateway)的连接。网关未启用时这一项是灰色的 |
| 解密 HTTPS | 分别为本机和代理网关开启 HTTPS 解密，见[解密 HTTPS](./https) |
| 根证书... | 管理用于解密的根证书 |

## 过滤

点 **过滤...** 选择范围：

![抓包过滤](/images/capture-filter.png){width=563}

- **全部**
- **仅匹配规则的连接（白名单）**
- **匹配规则之外的全部（黑名单）**

白名单或黑名单模式下，点 **添加...** 添加过滤规则。规则按应用程序、目标主机、端口书写，写法和[代理规则](./rules#条件)相同，填写的字段都满足才算命中，留空的字段不作限制。例如只抓某个程序，或者排除使用证书固定的程序。

![抓包规则](/images/capture-rule.png){width=402}

## 能抓到什么

列表里每行是一个连接，选中后下方显示详情。

### HTTP

HTTP/1.x 会被解析成一来一回的请求和响应，显示方法、地址、状态码、头部和正文。开启解密后，HTTPS 也会这样显示，协议一栏带锁形图标的就是解密后的连接。

### 其他 TCP

按收发方向分段，以十六进制和文本对照显示。

### DNS

两种拦截后端看到的 DNS 查询和应答，按“进程 + 本地端口 + DNS 服务器”归为一行，目标显示为“查询名 @ 服务器”，详情里解码出问题、应答码和记录。过滤按查询的域名匹配。

开启[通过代理解析主机名](./dns#通过代理解析主机名)时，程序收到的是 WinRoute 的占位应答，状态列显示“本地应答”。真实的解析发生在代理端，本机看不到。

### UDP

经 SOCKS5 转发的 UDP 按“进程 + 目标”归为一行，记录每个收发的数据报。

### 抓不到的

- 不走代理、也没有开启[处理直接连接](./advanced#处理直接连接)的直连 TCP；
- 不经代理转发的普通 UDP；
- WinRoute 自己的连接和 DNS 查询。

## 导出

点 **导出...** 后先弹出选项框：

![导出抓包](/images/capture-export.png){width=437}

- **范围**：默认导出全部连接。只想导出选中的连接时，要勾选“只导出选中的连接”，表格里选中了行不会自动缩小范围。
- **格式**：
  - **PCAPNG**：给 Wireshark 用。TCP 会合成握手和分段，Wireshark 可以重组成流；UDP 和 DNS 写成真实的 UDP 包。
  - **HAR**：只包含 HTTP 交互，可以导入浏览器开发者工具等。

### 解密后的 HTTPS 在 Wireshark 里如何显示

| 选项 | 效果 |
| --- | --- |
| 保留真实端口（443）（默认） | 要在 Wireshark 里对该端口用“Decode As → HTTP”，否则会被当成 TLS 解析而显示乱码 |
| 改用 80 端口 | Wireshark 直接按 HTTP 解析 |
| 保留真实端口且自动按 HTTP 显示 | 以 Exported PDU 格式写入，端口仍是 443，无需 Decode As；但没有 TCP 流视图，每个包最大 256 KB |
