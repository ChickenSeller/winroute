# 抓包

菜单：**工具 > 抓包**。启用后，主窗口中显示 **抓包** 标签页。

抓包功能记录经过 WinRoute 的连接所收发的应用层数据，用于分析应用程序的网络行为。记录的内容仅保存在本机内存中，不会上传。

![抓包页](/images/capture.png){width=1103}

首次开始抓包时，WinRoute 会提示：抓包内容仅保存在本机；启用 HTTPS 解密后，内容可能包含密码等敏感信息，导出或共享时请注意。

## 工具栏

| 控件 | 功能 |
| --- | --- |
| 开始 / 暂停 | 开始或暂停记录 |
| 清除 | 清空已记录的内容 |
| 导出... | 导出为 PCAPNG 或 HAR，参见下文 |
| 过滤... | 设置记录范围，参见下文 |
| 抓取：本机 | 记录本机应用程序的连接 |
| 抓取：代理网关 | 记录其他设备经由[代理网关](./gateway)建立的连接。代理网关未启用时此项不可用 |
| 解密 HTTPS | 分别为本机和代理网关启用 HTTPS 解密，参见[解密 HTTPS](./https) |
| 根证书... | 管理用于解密的根证书 |

## 过滤

单击 **过滤...** 选择记录范围：

![抓包过滤](/images/capture-filter.png){width=563}

- **全部**
- **仅匹配规则的连接（白名单）**
- **匹配规则之外的全部（黑名单）**

在白名单或黑名单模式下，单击 **添加...** 添加过滤规则。规则按应用程序、目标主机和端口设置，语法与[代理规则](./rules#条件)相同；所填写的条件全部满足时视为匹配，留空的条件不作限制。例如，可仅记录某一应用程序，或排除使用证书固定的应用程序。

![抓包规则](/images/capture-rule.png){width=402}

## 记录内容

列表中每行对应一个连接，选择后在右侧显示详细内容。

### HTTP

HTTP/1.x 会解析为请求和响应，显示方法、URL、状态码、头部和正文。启用解密后，HTTPS 连接也以此方式显示；协议列带有锁形图标的行即为已解密的连接。

### 其他 TCP

按发送方向分段，以十六进制和文本对照显示。

### DNS

两种拦截后端捕获的 DNS 查询和应答，按“进程 + 本地端口 + DNS 服务器”归为一行，目标显示为“查询名称 @ 服务器”，详细内容中解码显示问题、应答码和记录。过滤规则按查询的域名匹配。

启用[通过代理解析主机名](./dns#通过代理解析主机名)时，应用程序收到的是 WinRoute 返回的虚拟地址应答，状态列显示“本地应答”。实际解析在代理服务器一侧进行，本机无法记录。

### UDP

经由 SOCKS5 转发的 UDP 按“进程 + 目标”归为一行，记录收发的每个数据报。

### 无法记录的内容

- 未经代理、且未启用[处理直接连接](./advanced#处理直接连接)的直接 TCP 连接；
- 未经代理转发的 UDP；
- WinRoute 自身的连接和 DNS 查询。

## 导出

单击 **导出...** 后先显示选项对话框：

![导出抓包](/images/capture-export.png){width=437}

- **范围**：默认导出全部连接。如仅需导出所选连接，须勾选相应选项；在列表中选择行不会自动缩小导出范围。
- **格式**（在保存对话框中选择）：
  - **PCAPNG**：供 Wireshark 使用。TCP 连接合成握手和分段，可在 Wireshark 中重组为流；UDP 和 DNS 写为实际的 UDP 数据包。
  - **HAR**：仅包含 HTTP 交互，可导入浏览器开发者工具等。

### 解密后的 HTTPS 在 Wireshark 中的显示方式

| 选项 | 效果 |
| --- | --- |
| 保留真实端口（443）（默认） | 须在 Wireshark 中对该端口使用“Decode As → HTTP”，否则会被当作 TLS 解析而无法正确显示 |
| 改用 80 端口，Wireshark 自动按 HTTP 显示 | Wireshark 自动按 HTTP 解析 |
| 保留真实端口（443）且自动按 HTTP 显示 | 以 Exported PDU 格式写入，端口仍为 443，无需 Decode As；但无 TCP 流视图，单个数据包最大 256 KB |
