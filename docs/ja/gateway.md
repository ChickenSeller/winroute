# プロキシゲートウェイ

ツールバー：**プロキシゲートウェイ**。

プロキシゲートウェイは、WinRoute を HTTP および SOCKS5 プロキシサーバーとして動作させます。ローカルネットワーク上の他の端末（スマートフォン、テレビ、ゲーム機、仮想マシン、他のコンピューター）は、このコンピューターをプロキシサーバーとして設定することで、このコンピューター経由でネットワークにアクセスし、ここで設定したプロキシやチェーンを利用できます。

## 設定

![プロキシゲートウェイウィンドウ](/images/ja/gateway.png){width=721}

### 有効化

**プロキシ機能を有効にし、他のマシンがこのマシン経由でネットワークにアクセスできるようにします** をオンにします。これがこの機能全体のスイッチです。

### 待ち受け

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| アドレス | `0.0.0.0` | 待ち受けるアドレス。既定ではすべてのネットワークアダプターです。特定のネットワークのみに提供する場合は、そのアダプターのアドレスを入力します |
| HTTP ポート | 8080 | HTTP プロキシ。CONNECT と通常の HTTP 要求に対応します。個別に無効にできます |
| SOCKS5 ポート | 1080 | SOCKS5 プロキシ。個別に無効にできます |

### 送信接続

| 方式 | 説明 |
| --- | --- |
| このマシンのプロキシルールに従う | このコンピューターの[プロキシ化ルール](./rules)に従って処理します。リモートからの接続にはローカルのプロセスがないため、アプリケーションで指定したルールはスキップされます |
| 常に直接接続する | プロキシを経由せずに直接ネットワークに接続します |
| すべての接続を指定したプロキシまたはチェーン経由にする | すべての接続が選択したプロキシまたはチェーンを経由します |

**すべての接続を指定したプロキシまたはチェーン経由にする** を選択した場合、**選択したプロキシに接続できない場合** で次のいずれかを選択できます。

- **ブロック**：接続を拒否し、通信がプロキシを迂回しないようにします。
- **直接接続する**：代わりに直接接続します。

### 認証

ユーザー名とパスワードを設定すると、クライアントは認証が必要になります。SOCKS5 ではユーザー名/パスワード認証、HTTP では Basic 認証を使用します。

ユーザー名を空欄にすると、クライアントは認証なしでゲートウェイを使用できます。

::: warning
認証を設定しない場合、同じネットワーク上のどの端末からもゲートウェイを使用できます。信頼できるネットワークでのみ使用してください。
:::

## 他の端末からの利用

このコンピューターのローカル IP アドレスが `192.168.1.10` の場合の例：

- **HTTP プロキシ**：サーバー `192.168.1.10`、ポート `8080`。スマートフォンの Wi-Fi 設定にあるプロキシは通常この種類です。
- **SOCKS5 プロキシ**：サーバー `192.168.1.10`、ポート `1080`。

::: tip 接続できない場合
- Windows ファイアウォールで、他の端末からこれらのポートへのアクセスが許可されていることを確認してください。
- 端末がこのコンピューターと同じネットワークにあり、ルーターでクライアントの分離（AP アイソレーション）が有効になっていないことを確認してください。
- ログで、その端末からの接続や認証の失敗が記録されていないか確認してください。
:::

## ゲートウェイの通信の確認

- **接続一覧**：ゲートウェイの接続は `[Gateway] 端末の IP` と表示されます。
- **トラフィックグラフ**：ゲートウェイの実行中は、ゲートウェイの受信と送信の曲線が表示されます。
- **ログ**：各接続が一致したルールと使用したアダプターが記録されます。
- **パケットキャプチャ**：**キャプチャ：プロキシゲートウェイ** をオンにすると記録でき、[HTTPS の復号](./https#プロキシゲートウェイ利用端末の復号)も可能です。
