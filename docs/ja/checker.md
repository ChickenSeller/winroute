# プロキシチェッカー

メニュー：**ツール > プロキシチェッカー...**、またはツールバーの **プロキシチェッカー**。

テストするプロキシサーバーまたはチェーンを選択し、**接続先ホスト** と **ポート** を入力して、**テスト開始** をクリックします。

![プロキシチェッカー](/images/ja/checker.png){width=623}

## テスト項目

WinRoute は次のテストを順に実行し、それぞれの結果と所要時間を表示します。

1. **接続テスト**：プロキシサーバーに接続できるかどうか。
2. **プロキシサーバー経由の接続テスト**：プロキシサーバー経由で接続先ホストに接続できるかどうか。
3. **HTTP 要求テスト**：プロキシサーバー経由で HTTP 要求を送信し、応答のステータスを表示します。ポートが 443 の場合は、先に **TLS ハンドシェイクテスト** を実行します。
4. **UDP 対応テスト**：SOCKS5 プロキシのみが対象です。プロキシサーバーに UDP リレーを要求し、そのリレー経由で `8.8.8.8` に DNS 照会を送信します。応答があれば、そのプロキシは UDP を転送できます。
5. **UDP 到達性・NAT テスト（STUN）**：SOCKS5 プロキシのみが対象です。リレー経由で複数の公開 STUN サーバーへ同時にリクエストを送り、プロキシが **任意のホスト** へ UDP を届けられるか（DNS だけでないか）を確認します。さらに 2 台のサーバーが見た公開エンドポイントを比較して、出口の NAT マッピングを判定します。**エンドポイント非依存（フルコーン）** は P2P ゲーム向き、**対称型** は通常の UDP が通っても Steam リレーなどの P2P はおそらく失敗します。サーバーはプリセット（名前はチェックボックス、アドレスはツールチップ）から選ぶか、**カスタム** 欄で追加します（`host:port`、`;` またはスペース区切り）。テスト全体はタイトルのチェックボックスで無効化でき、一部のサーバーに到達できなくても許容されます（1 台でも応答すれば到達可能と判定）。

テストが完了すると、プロキシサーバーが正常に動作していることが表示されるか、失敗した段階でその理由が表示されます。例：

- 認証に失敗しました
- プロキシは認証が必要です
- 10 秒以内に応答がありません
- SOCKS5 プロキシではありません
- 5 秒以内にリレーから応答がありません（UDP がブロックされている可能性があります）

UDP 関連テストの失敗は全体の結果に影響しません。そのプロキシサーバーが UDP を転送できないことを示すだけです。

::: tip
**UDP 対応テスト** はリレーが DNS の往復を 1 回こなせることを示すだけです。一部のプロキシはポート 53 の UDP だけを転送するため（ポートで分岐する xray 設定で多い）、ここでは成功と出てもゲームの接続は失敗します。**UDP 到達性・NAT テスト** はこの 2 つを見分けるためのものです。
:::

::: tip
プロキシサーバーを追加または編集するウィンドウの **チェック** ボタンからも、このツールを開けます。
:::
