# 名前解決

メニュー：**プロファイル > 名前解決...**、またはツールバーの **名前解決**。

![名前解決ウィンドウ](/images/ja/name-resolution.png){width=623}

## 解決方式

### DNS 設定を自動的に検出する（既定）

ローカルの DNS が利用できる場合はローカルで解決し、利用できない場合は自動的にプロキシサーバーで解決します。現在の方式はステータスバーとログに表示されます。

### プロキシ経由でホスト名を解決する

この項目をオンにするには、先に **DNS 設定を自動的に検出する** をオフにしてください。

アプリケーションがホスト名を照会すると、WinRoute は `198.18.0.0/15` の範囲の仮の IP アドレスを返します。アプリケーションがそのアドレスに接続すると、WinRoute は実際のホスト名をプロキシサーバーに送信し、プロキシサーバーが解決します。仮のアドレスは WinRoute の実行中のみ有効です。

この方式には次の効果があります。

- アクセス先のホスト名がローカルネットワークやローカルの DNS サーバーに知られません。
- プロキシ側でのみ解決できるホスト名（プロキシの内部ネットワークにあるホストなど）にアクセスできます。
- プロキシサーバーに近いサーバーのアドレスに解決されます。

仮のアドレスへの接続が **直接接続** ルールに一致した場合、WinRoute はホスト名をローカルで解決してから直接接続します。

## 名前の一覧

プロキシで解決するホスト名を限定できます。

- **次の名前は解決しない**（既定）：一覧の名前はローカルで解決し、それ以外はプロキシで解決します。既定の一覧は `%ComputerName%; localhost; *.local` です。
- **次の名前のみ解決する**：一覧の名前のみをプロキシで解決します。

一覧には `%ComputerName%`（このコンピューターの名前）と `%SimpleHostnames%`（ドットを含まないホスト名）を使用できます。

## 注意事項

- この機能は DNS の捕捉に依存しており、NetFilter と WinDivert の両方の捕捉方式で利用できます。
- DNS over HTTPS を使用するブラウザーはシステムの DNS を経由しないため、WinRoute はその照会を取得できません。必要に応じて、ブラウザーの設定で「セキュア DNS」をオフにしてください。
- DNS の照会をログに記録するには、[DNS をログに表示](./advanced#dns-をログに表示)を有効にしてください。
