# HTTPS の復号

有効にすると、キャプチャ内の HTTPS 接続が平文で表示されます。

## 仕組み

WinRoute は、キャプチャ対象となる 443 番ポートへの接続を中間者として復号します。

1. アプリケーションの TLS ハンドシェイクからホスト名（SNI）を読み取り、WinRoute のルート証明書でそのホスト名の一時的な証明書を発行して、アプリケーションと TLS 接続を確立します。
2. 同時に、クライアントとして実際のサーバーに接続し、サーバーの証明書を検証します。
3. 2 つの TLS 接続の間でデータを転送するため、キャプチャには平文が記録されます。

実際のサーバーの証明書の検証に失敗した場合、WinRoute は接続を閉じ、信頼できないサーバーをアプリケーションに提示しません。

## このコンピューターのアプリケーションの復号

1. キャプチャタブで **HTTPS を復号：このコンピューター** をオンにし、**キャプチャ：このコンピューター** がオンで、キャプチャが開始されていることを確認します。
2. ルート証明書がまだない場合は、証明書の **共通名**、**組織**、**有効期間** の入力を求められ、証明書が生成されて Windows の「信頼されたルート証明機関」にインストールされます。
3. Chrome や Edge など、システムの証明書ストアを使用するアプリケーションはこの証明書を信頼します。

::: tip Firefox
Firefox は独自の証明書ストアを使用します。**ルート証明書...** で証明書をエクスポートし、Firefox の「設定 > プライバシーとセキュリティ > 証明書 > 証明書を表示 > 認証局証明書」でインポートしてください。
:::

## プロキシゲートウェイ利用端末の復号

1. キャプチャタブで **HTTPS を復号：プロキシゲートウェイ** をオンにし、**キャプチャ：プロキシゲートウェイ** がオンであることを確認します。
2. ルート証明書がまだない場合は、WinRoute が証明書を作成します。この証明書は他の端末で使用するためのもので、このコンピューターにはインストールされません。
3. **ルート証明書...** で証明書（`.crt`）を **エクスポート** し、スマートフォンや他のコンピューターなどの端末に、信頼されたルート証明書としてインストールします。
4. SOCKS5 または HTTP CONNECT 経由で 443 番ポートに接続したものだけが復号されます。

このコンピューターとプロキシゲートウェイの復号の設定は独立しており、どちらか一方のみを有効にすることもできます。

## ルート証明書の管理

![ルート証明書ウィンドウ](/images/ja/root-cert.png){width=570}

**ルート証明書...** ウィンドウには、証明書の状態（未作成、作成済みだがこのコンピューターでは未信頼、作成済みでこのコンピューターで信頼済み）、共通名、組織、有効期間、SHA-256 フィンガープリントが表示され、次の操作を実行できます。

| ボタン | 機能 |
| --- | --- |
| 生成... / 再生成... | ルート証明書を作成します。再生成した場合は、すべての端末に新しい証明書をインストールする必要があります |
| インストール | このコンピューターの「信頼されたルート証明機関」にインストールします |
| 削除 | 上記のストアから削除します |
| エクスポート... | `.crt` ファイルとして保存し、他の端末や Firefox でインポートできるようにします |

::: danger 秘密鍵の管理
ルート証明書の秘密鍵は `%APPDATA%\WinRoute\ca` に保存されます。秘密鍵を入手した者は、この証明書を信頼する端末に対して任意のウェブサイトになりすますことができます。秘密鍵は公開しないでください。また、復号が不要になったら、このコンピューターと他の端末から証明書を削除してください。
:::

## 制限事項

- TCP の 443 番ポートのみを復号します。
- HTTP/2 は HTTP/1.1 にネゴシエートされます。UDP を使用する QUIC（HTTP/3）は復号されません。
- 証明書のピン留めを行うアプリケーションは接続を拒否します。[キャプチャフィルター](./capture#フィルター)で除外してください。
