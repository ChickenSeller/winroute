# 上流プロキシ

メニュー：**プロファイル > 上流プロキシ...**、またはツールバーの **上流プロキシ**。

このウィンドウでは、WinRoute が使用するプロキシサーバーと、それらで構成する[プロキシチェーン](./chains)を管理します。

![上流プロキシウィンドウ](/images/ja/proxies.png){width=584}

## プロキシサーバーの追加

**追加...** をクリックし（既存のプロキシを編集する場合はダブルクリック）、次の項目を設定します。

![プロキシサーバーウィンドウ](/images/ja/proxy-edit.png){width=505}

### アドレスとポート

プロキシサーバーの IP アドレスまたはホスト名です。IPv4 と IPv6 に対応しています。

### プロトコル

| プロトコル | 説明 |
| --- | --- |
| SOCKS バージョン 5 | 最も一般的なプロトコルです。ユーザー名とパスワードによる認証に対応し、UDP を転送できる唯一のプロトコルです |
| SOCKS バージョン 4 | 「SOCKS 4A 拡張を使用する」をオンにすると、ホスト名をプロキシサーバーで解決します |
| HTTPS | CONNECT トンネルに対応した HTTP プロキシです。任意の TCP 接続を転送でき、Basic 認証に対応しています |
| HTTP | HTTP 接続にのみ使用できます。事前に **プロファイル > 詳細設定 > HTTP プロキシサーバー...** で有効にする必要があります |

::: warning HTTP と HTTPS の違い
ここでの「HTTPS プロキシ」は、CONNECT メソッドに対応したプロキシサーバーを指します。「HTTP プロキシ」とされるサーバーの多くは CONNECT に対応しているため、HTTPS として追加してください。CONNECT に対応していないことが明らかな場合にのみ HTTP を選択します。
:::

### 認証

**有効** をオンにし、ユーザー名とパスワードを入力します。NTLM 認証と Kerberos 認証には対応していません。

パスワードのプロファイルへの保存方法については、[詳細設定 › パスワードの暗号化](./advanced#パスワードの暗号化)を参照してください。

### チェック

保存する前に **チェック** をクリックすると、[プロキシチェッカー](./checker)でプロキシサーバーをテストできます。

## 詳細設定

プロキシサーバーウィンドウで **詳細設定...** をクリックします。

![プロキシサーバーの詳細設定](/images/ja/proxy-advanced.png){width=391}

- **カスタムラベル**：既定の「アドレス:ポート」の代わりに、プロキシ一覧、ルール、プロキシチェッカーに表示されます。複数のプロキシを区別するのに使用します。
- **可能な場合はプロキシ要求に接続先のホスト名を使用する**：IP アドレスではなくホスト名をプロキシサーバーに送信します。IP アドレスを受け付けないプロキシサーバーに使用します。また、プロキシサーバー側で近いアドレスに解決させることができます。

## 既定のプロキシとして使用

新しいプロキシを保存すると、既定のプロキシとして使用するかどうかを確認するメッセージが表示されます。**はい** を選択すると Default ルールのアクションがこのプロキシに設定され、他のルールに一致しないすべての接続がこのプロキシを経由します。

## プロキシの削除

ルールで使用中のプロキシを削除すると、影響を受けるルールが一覧表示され、次のいずれかを選択できます。

- それらのルールも削除する
- それらのルールのアクションを、別のプロキシ、チェーン、直接接続、またはブロックに変更する

Default ルールは削除できません。アクションのみ変更できます。
