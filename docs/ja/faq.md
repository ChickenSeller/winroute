# よくある質問

## アプリケーションがプロキシ経由で接続しない

1. ログで、その接続が一致したルールを確認してください。ルールは上から順に照合されるため、上位にある条件の広いルールが先に一致している可能性があります。
2. アプリケーションが Windows サービスである場合や、他のユーザーとして実行されている場合は、[サービスと他のユーザー](./advanced#サービスと他のユーザー)で該当する項目を有効にしてください。
3. UDP は既定でそのまま通過します。[UDP を SOCKS5 で転送](./advanced#udp-を-socks5-で転送)を有効にし、ルールのアクションを単一の SOCKS5 プロキシにしてください。ブラウザーの QUIC（HTTP/3）は UDP 通信です。
4. ping と tracert は ICMP を使用するため、プロキシ経由で転送できません。

## しばらくするとすべての接続が機能しなくなる

デモドライバーでは、捕捉した接続の総数が上限に達すると動作が停止し、Windows の再起動が必要になります。**ツール > ネットワークドライバー** でドライバー A または B、あるいは WinDivert に切り替えてください。[インストールとネットワークドライバー](./install#捕捉方式とドライバーの変更)を参照してください。

## ローカルのプロキシクライアント（v2ray、Clash など）自身の接続も転送され、ループが発生する

[接続ループの検出](./advanced#接続ループの検出)が有効になっていることを確認してください。WinRoute はプロキシのポートで待ち受けているプロセスを識別し、その接続を直接接続にします。そのプログラムに **直接接続** ルールを作成し、一覧の最上位に配置することもできます。

## プロキシサーバーがホスト名のみを受け付け、IP アドレスを受け付けない

プロキシの **詳細設定...** で[可能な場合はプロキシ要求に接続先のホスト名を使用する](./proxies#詳細設定)をオンにするか、[プロキシ経由でホスト名を解決する](./dns#プロキシ経由でホスト名を解決する)を有効にしてください。

## HTTPS の復号を有効にすると、ブラウザーで証明書エラーが表示される

その端末が WinRoute のルート証明書を信頼していません。このコンピューターでは **ルート証明書...** で **インストール** をクリックしてください。Firefox や他の端末では、証明書をエクスポートして手動でインポートしてください。特定のアプリケーションでのみエラーが続く場合は、証明書のピン留めを行っている可能性があるため、キャプチャフィルターで除外してください。[HTTPS の復号](./https)を参照してください。

## 他の端末からプロキシゲートウェイに接続できない

Windows ファイアウォールでゲートウェイのポートが許可されていること、端末がこのコンピューターと同じネットワークにあること、ルーターでクライアントの分離が有効になっていないことを確認してください。[プロキシゲートウェイ](./gateway#他の端末からの利用)を参照してください。

## Proxifier と併用できるか

プロファイルは相互にインポート・エクスポートできますが、どちらもネットワーク接続を捕捉するため、同時に実行することはできません。
