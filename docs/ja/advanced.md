# 詳細設定

これらの設定は **プロファイル > 詳細設定** メニューにあり、プロファイルとともに保存されます。

## HTTP プロキシサーバー

有効にすると、[上流プロキシ](./proxies)で HTTP プロトコルのプロキシサーバーを追加できます。HTTP プロキシは HTTP 接続（ブラウザーなど）にのみ使用できます。HTTPS プロキシと混同しないでください。

## サービスと他のユーザー

既定では、現在のユーザーが実行するアプリケーションのみを処理します。次の項目を追加で選択できます。

- **Windows サービスとその他のシステムプロセス**
- **このコンピューターで他のユーザーが実行するアプリケーション**

::: info
これらの設定は TCP と UDP にのみ適用されます。ping や tracert が使用する ICMP は、プロキシ経由で転送できません。
:::

## 直接接続を処理する

- **オフ**（既定）：**直接接続** ルールに一致した接続は WinRoute を経由しません。一覧への表示や集計は行われず、負荷が最小限になります。
- **オン**：直接接続も WinRoute を経由します。一覧に表示され、トラフィックと統計に含まれ、[パケットキャプチャ](./capture)で記録できます。

[ネットワークインターフェイスを指定した](./rules#ネットワークインターフェイスの指定)ルールの直接接続は、常に WinRoute を経由します。

## 接続ループの検出

接続のループを防ぎます。有効にしておくことをお勧めします。

- 接続先がプロキシサーバー自体である場合は、直接接続します。
- プロキシサーバーがこのコンピューター上にある場合（`127.0.0.1:1080` で待ち受けるプロキシクライアントなど）、そのポートで待ち受けているプロセス自身の接続は、そのプロセスに送り返されずに直接接続されます。

ループを検出すると、プロセスごとに一度ログに通知されます。

## UDP を SOCKS5 で転送

既定では、UDP 通信はそのまま通過します。有効にすると、アクションが **単一の SOCKS5 プロキシ** であるルールに一致した UDP 通信（ゲームや音声通話など）を、SOCKS5 の UDP ASSOCIATE で転送します。

- プロキシチェーン、SOCKS4 プロキシ、HTTPS プロキシは UDP に対応していないため、該当する通信は直接送信され、ログに一度通知されます。
- プロキシサーバーが UDP に対応していない場合も直接送信されます。プロキシサーバーが UDP に対応しているかどうかは、[プロキシチェッカー](./checker)で確認できます。

これはグローバルの既定値で、ルールごとに上書きできます。[プロキシルール > UDP](./rules#udp) を参照してください。

## DNS をログに表示

DNS の照会をログに記録します。ホスト名に基づくルールのトラブルシューティングに役立ちます。

## パスワードの暗号化

プロキシのパスワードをプロファイルに保存する方法を設定します。

| 方式 | 説明 |
| --- | --- |
| 無効 | 平文で保存します。プロファイルを読み取れる人は誰でもパスワードを取得できます |
| 基本 | WinRoute の固定キーで暗号化します。WinRoute でプロファイルを開いた人は誰でもパスワードを使用できます |
| 現在のユーザーアカウント | 現在の Windows ユーザーの資格情報で暗号化します。そのユーザーのみがパスワードを使用できます |

プロファイルのマスターパスワードには対応していません。
