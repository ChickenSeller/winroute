# プロキシ化ルール

メニュー：**プロファイル > プロキシ化ルール...**、またはツールバーの **プロキシ化ルール**。

![プロキシ化ルールウィンドウ](/images/ja/rules.png){width=863}

## 評価順序

新しい接続は上から順にルールと照合され、**最初に一致した** ルールによって処理されます。それ以降のルールは評価されません。

- 一覧の末尾にある **Default** ルールは、他のルールに一致しないすべての接続を処理します。このルールは削除できず、アクションのみ変更できます。
- ルールを選択し、右側の上下の矢印で順序を変更します。条件が具体的なルールほど上に配置してください。
- **複製** をクリックすると、選択したルールを複製します。
- ルールの前にあるチェックボックスをオフにすると、そのルールを一時的に無効にできます。
- 一覧の **アクション** 列で、ルールのアクションを直接変更できます。

ルールをダブルクリックするか **編集...** をクリックすると、ルールウィンドウが開きます。

![プロキシ化ルールの編集ウィンドウ](/images/ja/rule-edit.png){width=563}

## 条件

3 つの条件をすべて満たした場合にのみ、ルールに一致します。空欄は「任意」を意味します。複数の値はセミコロンで区切ります。

### アプリケーション

プログラム名、フルパス、フォルダー、ワイルドカード：

```
chrome.exe; "C:\some app.exe"; C:\Games\; fire*.exe
```

- ファイル名のみの場合、任意の場所にある同名のプログラムに一致します。
- フォルダー（末尾が `\`）の場合、そのフォルダー内のすべてのプログラムに一致します。
- 空白を含むパスは二重引用符で囲んでください。
- **参照...** ドロップダウンメニューの **ファイルを追加...** または **フォルダーを追加...** で選択することもできます。

### 接続先ホスト

IP アドレス、ホスト名、ワイルドカード、IP アドレス範囲：

```
127.0.0.1; *.example.com; 192.168.1.*; 10.1.0.0-10.5.255.255
```

アプリケーションが IP アドレスで接続した場合も、WinRoute はそれ以前の DNS 応答からホスト名を復元するため、ホスト名で指定したルールが適用されます。

### 接続先ポート

単一のポートまたはポート範囲：

```
80; 443; 8000-9000
```

## アクション

| アクション | 説明 |
| --- | --- |
| 直接接続 | プロキシを経由せずに接続します |
| ブロック | 接続を拒否します |
| プロキシ | 選択したプロキシサーバー経由で接続します |
| チェーン | 選択したプロキシチェーン経由で接続します |

## ネットワークインターフェイスの指定

ルールウィンドウで **詳細設定...** をクリックすると、ルールに一致した接続を特定のネットワークアダプターから送信できます。

![ルールのネットワークインターフェイス](/images/ja/rule-interface.png){width=443}

- 直接接続の場合は、そのアダプターから接続先ホストに接続します。
- プロキシ経由の場合は、そのアダプターから最初のプロキシサーバーに接続します。

有線ネットワークとモバイルネットワークを併用している場合や、企業 VPN を使用している場合など、複数のネットワーク接続を持つコンピューターで役立ちます。

**インターフェイスが切断されているとき** は、次のいずれかを選択できます。

- **システムの既定のインターフェイスを使う**：通常どおり接続し、アダプターはシステムが選択します。
- **このルールを無視する（次に一致するルールを適用）**：特定のネットワークでのみ有効にするルールに使用します。

::: warning
選択したアダプターに接続先への経路がない場合、他のアダプターは使用されず、接続は失敗します。名前解決には引き続きシステムの既定の経路が使用されます。
:::

インターフェイスは GUID で保存され、Proxifier 4 のルールのネットワークインターフェイスと同じ形式のため、両者のプロファイルを相互に読み込めます。UDP の転送とプロキシゲートウェイも、ルールで指定したインターフェイスに従います。

## ホスト名の解決

**詳細設定...** ウィンドウの **名前解決** では、ルールごとにホスト名の解決方法を指定できます。ルールの設定は、プロファイルの[名前解決](./dns)の設定より優先されます。個別に指定していないルールは、プロファイルの設定に従います。

**ホスト名の解決**：

| オプション | 説明 |
| --- | --- |
| 名前解決の設定に従う（既定） | プロファイルの名前解決の設定に従います |
| プロキシ経由で解決 | **解決に使うプロキシ** で選択したプロキシが解決します。プロファイルのスイッチとドメインリストには左右されません |
| このコンピューターで解決 | ホスト名をこのコンピューターで解決します。プロキシ経由の場合は IP アドレスをプロキシサーバーに送信します |

**解決に使うプロキシ**（「プロキシ経由で解決」の場合）：

- **ルールの出口**：ホスト名をルールのプロキシまたはチェーンに送信し、そこで解決します。直接接続のルールには出口がないため、プロファイルでプロキシ経由の名前解決を手動で有効にしている場合は名前解決の設定の **直接接続の解決に使うプロキシ** の選択に従い、無効な場合はこのコンピューターで解決します。
- **指定したプロキシまたはチェーン**：WinRoute はそのプロキシ経由で、名前解決の設定の DNS サーバーに TCP で問い合わせ、得られた IP アドレスにルールどおり接続します。

ブロックのルールには、この設定は適用されません。

アプリケーションの DNS 問い合わせはすべて Windows の DNS Client サービスから送信されるため、問い合わせの時点ではアプリケーションを特定できません。そのため、プロファイルの「プロキシ経由でホスト名を解決する」が有効な場合はドメインリストで除外されたもの以外のすべてのドメインに、無効な場合は「プロキシ経由で解決」に設定したルールに一致する可能性があるドメインに、仮想 IP アドレスが返されます。接続時には、実際に一致したルールに従って解決方法が決まります。

## ルールのトラブルシューティング

ログには、各接続が一致したルール名と実際に使用したアダプターが記録されます。

```
chrome.exe - www.example.com:443 ルール ブラウザー に一致：プロキシ 203.0.113.10:1080 SOCKS5 経由で接続、アダプター イーサネット
```

ルールが機能しない場合は、ログでその接続が一致したルールを確認してください。上位に配置された条件の広いルールが先に一致していることがよくあります。

[接続一覧](./main-window#接続)で接続を右クリックし、**このアプリケーションのルールを作成...** を選択して、そのプログラムのルールを作成することもできます。
